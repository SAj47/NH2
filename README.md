# Not Human Service — Discord Bot

بوت ترحيب ورتب وسجلات (Logs) وصوت وذكاء اصطناعي (Gemini) لسيرفر **Not Human**.

## التشغيل

```
npm install
copy .env.example .env      ← ثم املأ DISCORD_TOKEN و CLIENT_ID و GEMINI_API_KEY
npm start
```

- `npm run dev` : يعيد تشغيل البوت تلقائياً عند حفظ أي ملف
- `npm test` : يشغّل كل الاختبارات (180 اختباراً، بدون إنترنت وبدون ديسكورد حقيقي)

عند كل تشغيل يطبع البوت **STARTUP CHECK**: تقرير يخبرك بأي خطأ في الـ IDs أو الرتب أو الصلاحيات أو مفتاح Gemini، مع طريقة الحل.
وفي ديسكورد يعطيك الأمر `/status` (للأدمن) نفس التقرير.

## الأوامر (Slash)

| الأمر | الوظيفة |
|---|---|
| `/ask prompt [image] [private]` | اسأل الـ AI (يقبل صورة للتحليل) |
| `/aireset` | يجعل الـ AI ينسى محادثتك |
| `/role add <name>` | اطلب رتبة من القائمة المسموحة (يفهم الأخطاء الإملائية والأسماء البديلة) |
| `/role remove <name>` | يزيل **أي** رتبة تملكها، عدا الرتب المحمية (انظر أدناه) |
| `/role list` | الرتب المتاحة للطلب وما تملكه منها |
| `/join [channel]` | يدخل روماً صوتياً ويبقى فيه بصمت تام (self-mute + self-deaf دائماً، لا يشغّل أي صوت) |
| `/leave` | يخرج من أي روم صوتي هو فيه |
| `/status` | فحص شامل للبوت (أدمن فقط) |
| `/ping` | سرعة الاستجابة |

إذا طلب عضو رتبة لا توجد ولا يوجد ما يشبهها عبر `/role add`: يعتذر البوت ويخبره أنها **قريباً**.

### الرتب المحمية من `/role remove`
أي رتبة اسمها يطابق `config.js > PROTECTED_ROLES` (افتراضياً: `boy` `girl` `gay` `admin`) لا يمكن سحبها عبر `/role remove` أبداً — يعتذر البوت ويطلب من العضو التواصل مع الإدارة، حتى لو كان يملكها فعلاً.

## الأوامر النصية القديمة الطراز (! )

| الأمر | من يستطيع استخدامه | الوظيفة |
|---|---|---|
| `!type <رسالة>` | فقط من يملك رتبة `config.js > ROLES.TYPING_ROLE_ID` (أو رتبة اسمها "typing") | يحذف رسالته الأصلية (إن أمكن) ويرسل النص كبطاقة رسمية من البوت |
| `!welcm` | فقط من يملك رتبة `config.js > ROLES.STAFF_ROLE_ID` (أو رتبة اسمها "staff") | يطلب تأكيداً، ثم يعيد إرسال بطاقة الترحيب لكل الأعضاء الحاليين كأن البوت انضم لتوّه. **لا** يعيد تعيين الرتب التلقائية. الترحيب العادي عند الدخول يستمر يعمل بشكل طبيعي أثناء وبعد ذلك |

## هيكل المشروع

```
index.js               ← لا تعدّله: يحمّل كل شيء تلقائياً
config.js              ← كل الإعدادات (IDs، الرتب، القنوات، حدود الـ AI، الأوامر النصية)
.env                    ← الأسرار (التوكن والمفاتيح) — لا تشاركه
assets/                 ← صورة الترحيب (welcome.jpg)
commands/               ← كل ملف = أمر Slash
events/                 ← كل ملف = حدث (الترحيب، الأوامر النصية، الفحص عند التشغيل)
  logs/                 ← أحداث السجلات (حظر، طرد، رسائل، رتب، صوت ...)
features/               ← المنطق (الترحيب، الرتب، الصوت، الـ AI، السجلات، الفحص)
services/gemini.js      ← الاتصال بـ Gemini
utils/                  ← أدوات مساعدة
tests/                  ← الاختبارات (180)
```

> كل ملف في المشروع له **اسم فريد** حتى لا يختلط عليك مكانه.

## إضافة ميزة جديدة (دون لمس index.js)

- **أمر جديد:** انسخ `commands/_template.js` باسم جديد (مثل `hello.js`) وعدّله.
- **حدث جديد:** انسخ `events/_template.js` وعدّله.
- ثم أعد تشغيل البوت. الملفات التي تبدأ بـ `_` تُتجاهل.
- إذا احتاجت الميزة Intent إضافي فاكتبه داخل ملفها في `intents: [...]`.

## إضافة رتب جديدة لـ `/role add`

في `config.js`:
```js
SELF_ROLES: {
    'gamer': '1550491420568330241',
    'beatmaker': 'ضع_ID_الرتبة_هنا'   // أضف رتباً أخرى بنفس الطريقة
},
ROLE_ALIASES: {
    'beatmaker': ['beats', 'producer', 'بيتميكر']   // أسماء بديلة تُفهم تلقائياً (اختياري)
}
```
`/status` يخبرك فوراً إن نسيت استبدال أي `PUT_ROLE_ID_HERE` بمعرّف حقيقي.

## قنوات الـ Logs

يجدها البوت تلقائياً بالاسم داخل كاتيغوري **Staff**:
`messages` `time・out` `roles` `rooms` `mouved` `muted・demute` `kicked` `banned` `unbanned` `join-membre` `left-membre`

لتحديد قناة بالـ ID ضعه في `config.js > LOGS.CHANNELS`.

## في Discord Developer Portal (Bot)

فعّل: **Server Members Intent** و **Message Content Intent**.
(`GuildVoiceStates` مفعّلة تلقائياً في الكود لكل من `/join` وسجل الصوت — ليست Privileged فلا حاجة لتفعيلها يدوياً في البورتال).

## صلاحيات البوت في السيرفر

`Manage Roles` • `View Audit Log` • `Connect` (للصوت) • وفي قنوات الترحيب و Staff: `View Channel` `Send Messages` `Embed Links` `Attach Files` `Manage Messages` (لحذف رسائل `!type`)
ورتبة البوت يجب أن تكون **فوق** الرتب التي يمنحها أو يسحبها.

## الاستضافة المجانية 24/7 على Render

على Render، **الفئة المجانية هي للـ "Web Service" فقط** (وليست لـ "Background Worker" التي لا فئة مجانية لها إطلاقاً). الفرق أن Web Service يُنيّمها Render تلقائياً بعد **15 دقيقة** من عدم استقبال أي طلب HTTP — حتى لو كان البوت نفسه متصلاً بديسكورد وشغّالاً. لهذا أضفت للمشروع سيرفر HTTP صغير جداً (داخل `index.js`) لا علاقة له بديسكورد، مهمته الوحيدة الرد "OK" حتى تستطيع خدمة مجانية خارجية "تنبيه" البوت كل بضع دقائق فيبقى مستيقظاً.

### 1) ارفع المشروع إلى GitHub
أنشئ مستودعاً جديداً وارفع كل الملفات **عدا `.env`** (موجود أصلاً في `.gitignore`).

### 2) أنشئ خدمة على Render
1. ادخل إلى [render.com](https://render.com) → **New** → **Web Service** (وليس Background Worker).
2. اربط مستودع GitHub الخاص بك.
3. الإعدادات:
   - **Build Command:** `npm install`
   - **Start Command:** `node index.js`
   - **Instance Type:** `Free`
4. من تبويب **Environment**، أضف نفس متغيرات ملف `.env` عندك (`DISCORD_TOKEN`, `CLIENT_ID`, `GEMINI_API_KEY`, وأي متغير آخر). **لا ترفع ملف `.env` نفسه.**
5. اضغط **Deploy**. بعد انتهاء البناء، Render يعطيك رابطاً مثل `https://your-bot.onrender.com` — هذا ما يُستخدم في الخطوة التالية.

### 3) امنع البوت من "النوم" (مجاناً)
أنشئ حساباً مجانياً في [UptimeRobot](https://uptimerobot.com) (أو [cron-job.org](https://cron-job.org))، وأضف **Monitor** جديداً:
- **Type:** HTTP(s)
- **URL:** رابط Render الذي حصلت عليه
- **Interval:** كل 10 إلى 14 دقيقة (أقل من 15 دقيقة، حد النوم عند Render)

هذه الخدمة ستزور رابط بوتك دورياً، فيبقى Render يعتبره "نشطاً" ولا ينيّمه أبداً.

### ما يجب معرفته (بصراحة)
- **750 ساعة مجانية شهرياً** لكل Workspace في Render. الشهر الواحد ≈ 744 ساعة، فتشغيل بوت واحد 24/7 بهذه الطريقة يستهلك كل الساعات تقريباً دون تجاوزها، لكن لا تضف خدمة مجانية ثانية في نفس الحساب وإلا نفدت الساعات قبل نهاية الشهر.
- **نظام الملفات مؤقت (ephemeral):** أي ملف يكتبه البوت أثناء التشغيل (غير الموجود في المستودع) يُحذف عند كل إعادة نشر. هذا لا يؤثر على مشروعك لأن كل شيء (بما فيها `assets/welcome.jpg`) موجود في المستودع نفسه.
- هذه الطريقة (سيرفر HTTP + تنبيه خارجي) هي الحل المجاني القياسي المستخدم لاستضافة بوتات ديسكورد على Render، لكنها ليست ميزة رسمية موثّقة من Render لهذا الغرض تحديداً — إن احتجت ضماناً رسمياً لعدم النوم إطلاقاً، فهذا متوفر فقط في الخطط المدفوعة (تبدأ من 7$/شهر تقريباً).

## إذا رأيت "The application did not respond" على أمر بسيط مثل `/ping`
هذا يعني أن عملية البوت كانت تعيد التشغيل في تلك اللحظة بالضبط (3 ثوانٍ فقط مهلة ديسكورد للرد الأول). البوت الآن يسجّل أي خطأ متزامن غير متوقَّع (`uncaughtException`) بوضوح في الـ logs بدل أن يختفي بصمت، فافتح **Logs** في Render وابحث عن `❌ Uncaught exception` قرب وقت الحدوث لمعرفة السبب الدقيق.
